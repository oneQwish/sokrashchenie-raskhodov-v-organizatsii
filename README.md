# Сокращение расходов в организации — кейс VitaStore

| Задание | Файлы |
|---|---|
| Task1. Карта бизнес-возможностей и Buy vs Build | `capability_map_heatmap.pdf` — карта L1/L2 с heatmap и пометкой дублей; `sourcing_strategy_matrix.md` — матрица Sourcing Strategy |
| Task2. Целевой процесс онбординга магазина | `vitastore_onboarding.bpmn` (Camunda Modeler) и `vitastore_onboarding.png`; `human_verification.md` — точки верификации человеком |
| Task3. Целевая облачная архитектура | `as_is_c4.png` — AS-IS, C4 Container (исправленная схема из артефакта 1); `to_be_hld.png` — To-Be HLD с Edge HAL; `offline_mode.md` — офлайн-режим и синхронизация; `*.puml` — исходники схем (PlantUML, C4) |
| Task4. TCO и ROI | `tco_analysis.xlsx` — модель TCO на формулах; `roi_conclusion.md` — вывод о ROI и сроке окупаемости |

Ключевые решения, общие для всех заданий:

- Слой абстракции оборудования (HAL) покупается в составе Cloud POS. Драйверы работают на смарт-терминале в магазине, управляются из облака.
- Онбординг: выгрузка базы старой кассы сверяется с эталонным каталогом по штрихкоду; позиции без совпадения сопоставляет AI-сервис. Уверенность 95% и выше — автоматически, ниже — товароведу, плюс выборочная проверка автоматических решений.
- Офлайн: наличные — всегда, карта — через собственный канал банковского терминала, чек печатает встроенный ФН.

---
*Реальный проект скорее всего изначально запускался бы без ИИ, с ручной довалидацией несхождений с таблицей. В зависимости от количества таких несхождений целесообразность внедрения и поддержки ИИ соразмерно изменяется.*
